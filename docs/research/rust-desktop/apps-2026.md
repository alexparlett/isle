Research for P19a (Monitor, §1–5), P19b (Cleaner, §8–9) and P19c (Keychain, §6–7). Host readings
were taken read-only on 2026-10-29; crate versions are crates.io's latest stable that day. Each
packet's plan takes these as evidence, not as its choices.

## 1. Per-process network traffic

Activity Monitor's Network tab shows, per process, Sent Bytes, Rcvd Bytes, Sent Packets, Rcvd Packets
(cumulative), plus totals and a rate graph.

- **sock_diag (`NETLINK_SOCK_DIAG`, `INET_DIAG_INFO`)**: dumps every TCP socket in the netns
  *unprivileged*, other users' included (kernel comment: tcp_diag metadata "can be exported to all
  users"; only MD5/ULP/mark extras need `CAP_NET_ADMIN`). `tcp_info` has `bytes_sent`, `bytes_acked`,
  `bytes_received`, `segs_out`, `segs_in`, `data_segs_*`, so all four columns exist for TCP.
  `ss -tie` on the host shows `cgroup:` per socket (`INET_DIAG_CGROUP_ID`, 5.7+), even for
  `systemd-resolve`'s sockets, so attribution to Isle's `app-isle-*.scope` needs no `/proc` access.
  Pid attribution via `/proc/<pid>/fd` → `socket:[ino]` works for own processes only.
  Gaps: **UDP has no counters** (`udp_diag` registers `idiag_info_size = 0`; `ss -uin` shows none),
  so game traffic and QUIC (Vivaldi/Chromium HTTP/3) are invisible; bytes on sockets that close
  between samples are lost; it is polling.
- **`/proc/<pid>/net/dev`**: that netns's interfaces, i.e. system-wide. Useless per process.
- **cgroup BPF accounting**: systemd's `IPAccounting=` is exactly a `cgroup_skb` ingress/egress
  pair counting bytes and packets per unit. The user manager cannot attach BPF (needs `CAP_BPF` +
  `CAP_NET_ADMIN`); the system manager can only account `user@1000.service` as a whole.
- **eBPF via aya with a privileged helper**: a small system service (`CapabilityBoundingSet=CAP_BPF
  CAP_NET_ADMIN CAP_PERFMON`, `DynamicUser=`) attaches `cgroup_skb/{ingress,egress}` to the cgroup2
  root with `BPF_F_ALLOW_MULTI`, counting bytes+packets keyed by `bpf_skb_cgroup_id()`. Covers TCP,
  UDP, QUIC, ICMP. Per-process inside an app needs a `cgroup/sock_create` hook tagging socket
  cookie → tgid. It serves read-only counters to the session over D-Bus or varlink. aya 0.16.0
  (2026-10-28), aya-ebpf 0.2.1; the BPF side needs nightly + `bpf-linker`.
- **libpcap with caps** (what others ship): KDE's `ksgrd_network_helper` needs `setcap cap_net_raw`
  and packagers often miss it; Mission Center 1.0's per-process network "requires nethogs" made
  runnable without root. Both sniff packets and match them to `/proc/net/*` inodes: costly under
  game load.

**Recommendation**: per **app** (cgroup), not per pid, matching how Isle launches apps in scopes.
The target is the aya `cgroup_skb` helper, because UDP is most of the traffic on a gaming machine.
P19 ships the sock_diag/`INET_DIAG_CGROUP_ID` path as the no-helper fallback labelled "TCP only",
with the helper as its own slice if a system service is in scope. Crates: `netlink-packet-sock-diag`
0.5.0 + `netlink-sys` 0.9.0, or a hand-rolled request on `rustix` 1.1.6 (it is ~100 lines).

Evidence: [tcp_diag.c](https://code.amethyst.name/public-mirrors/linux/src/branch/master/net/ipv4/tcp_diag.c), [udp_diag.c](https://git.disroot.org/kpriv/linux-hardened/src/commit/c752023aab5856559a295d045530af89cc51df06/net/ipv4/udp_diag.c), [sock_diag(7)](https://www.mankier.com/7/sock_diag), [KDE network helper README](https://lxr.kde.org/source/plasma/libksysguard/processcore/plugins/network/README.md), [Mission Center 1.0 needs nethogs](https://www.omgubuntu.co.uk/2025/05/mission-center-1-0-adds-new-features), [user manager and BPF](https://kernsec.org/pipermail/linux-security-module-archive/2019-August/015877.html).

## 2. GPU figures

- **NVIDIA**: NVML only. The open module 615.78.08 exposes **no DRM fdinfo**: the compositor's
  `card2`/`renderD129` fdinfo has only `pos/flags/mnt_id/ino`, no `drm-*` keys. No hwmon either.
  `nvml-wrapper` 0.13.0 (already in `isle-sysinfo`): `utilization_rates`, `memory_info`,
  `power_usage`, `total_energy_consumption` (mJ counter), `temperature`, `fan_speed(_rpm)`,
  `encoder_utilization`/`decoder_utilization`, `running_graphics_processes_v2` /
  `running_compute_processes_v2` (per-pid `used_gpu_memory`), and
  `process_utilization_stats(last_seen_ts)` (per-pid sm/mem/enc/dec samples). The samples are empty
  for idle processes: `nvidia-smi pmon` showed `-` for the compositor and 43–44% sm for a running game.
  Pids are global, so check uid before showing names.
- **amdgpu / Intel (i915, xe)**: DRM fdinfo per open fd: `drm-driver`, `drm-pdev`, `drm-client-id`,
  `drm-engine-<gfx|compute|dec|enc…>` (ns busy, cumulative), `drm-memory-*` / `drm-total-*` /
  `drm-resident-*`; i915/xe add `drm-cycles-*` / `drm-total-cycles-*`. Deduplicate by `drm-client-id`
  (dup'd fds share a client). Own processes only (fdinfo needs ptrace-read). System-wide amdgpu:
  `device/gpu_busy_percent`, `vcn_busy_percent`, `mem_info_vram_used/total`,
  `mem_info_gtt_used/total`, and `gpu_metrics` (binary, world-readable); hwmon gives edge temp,
  sclk and PPT.
- Map `pdev` to the card via `/sys/class/drm/card*/device` → PCI slot; names from `pciid-parser`
  0.8.1 or `/usr/share/hwdata/pci.ids`.

**Recommendation**: a `Gpu` trait with two backends, NVML (system + per-pid) and fdinfo+sysfs
(amdgpu/i915/xe). Do not rely on NVIDIA fdinfo. `nvtop`/`all-smi` (0.28.1) are references, not
dependencies. Evidence: [drm-usage-stats](https://docs.kernel.org/gpu/drm-usage-stats.html), host fdinfo.

## 3. Sensors and energy

- **hwmon**: enumerate `/sys/class/hwmon/hwmon*/name`, then `{temp,fan,in,power,curr,energy,freq}N_{input,label}`,
  plus `device` → PCI/platform for grouping. Labels are uneven: `k10temp` (Tctl/Tccd1), amdgpu
  (edge/PPT), and nvme (Composite) are good; `nct6687` voltages are VIN0..7 and its fans have no
  labels, so the board needs a curated map or "Fan 1". Hide fans at 0 rpm and `in*` by default.
  Crates: hand-rolled (≈ what `isle-sysinfo::cpu_temp` already does); `libmedium` 0.13.4 (typed,
  last release 2025-08); `lm-sensors` 0.5.1 binds libsensors (C dependency, and it adds nothing
  over sysfs here). `sysinfo` 0.40.0 `Components` covers temperatures only.
- **RAPL**: AMD Zen RAPL is in powercap through `intel_rapl_msr` (since 5.11); `energy_uj` has been
  root-only since the PLATYPUS fix (CVE-2020-8694). `amd_energy` was *removed* in 5.13 rather than
  opened up. btop reads `intel-rapl:0/energy_uj` and silently hides CPU watts when it is
  unreadable. s-tui does the same unless run as root.
- **Unprivileged CPU package power on this host**: amdgpu's `power1_input` (PPT) on the Granite
  Ridge iGPU read **69 W with the iGPU idle** (`gpu_busy_percent` 0) during a game. This is the
  SMU's socket power, world-readable. **Confirmed 2026-10-29** against RAPL's `energy_uj` as
  root, six 5 s windows each: idle, RAPL 37.1 W and PPT 38.7 W on average (+4%, single windows
  up to 12% apart); under a game, 84.4 W and 85.8 W (+1.6%). The driver reports `power1_input`
  in **milliwatts** here (36000 for 36 W), not the microwatts the hwmon ABI says.
- **Per-process energy**: Apple's Energy Impact is an undocumented weighted sum (CPU time, wakeups,
  GPU, disk, network) with per-model coefficients in `/usr/share/pmenergy`; 1 EI ≈ 10 ms/s of CPU
  (Chromium's `energy_impact_mac.h`). Mozilla calls it a poor measure. GNOME System Monitor and
  Plasma System Monitor have no per-process energy; powertop estimates watts from CPU share and
  wakeups.

**Recommendation**: hand-rolled hwmon with a small label override table. CPU watts come from
amdgpu PPT when the iGPU is on-package, else RAPL if readable, else hidden. Do not chmod
`energy_uj`. "Energy" per app = CPU-time share × package W + NVML/fdinfo GPU share × GPU W, shown
in watts, with a Wakeups column from Δ(`voluntary_ctxt_switches` + `nonvoluntary_ctxt_switches`)
and a 12-hour average from the sampler's history. Evidence: [amd_energy removal](https://www.phoronix.com/news/Linux-5.13-AMD-Energy-Removed), [AMD RAPL powercap](https://lkml.iu.edu/hypermail/linux/kernel/2010.3/02739.html), [btop source](https://github.com/aristocratos/btop/blob/main/src/linux/btop_collect.cpp), [Chromium EI](https://chromium.googlesource.com/chromium/src/+/9e001703a2/components/power_metrics/energy_impact_mac.h), [Mozilla on EI](https://firefox-source-docs.mozilla.org/performance/activity_monitor_and_top.html), [Eclectic Light 2026](https://eclecticlight.co/2026/06/29/what-does-activity-monitor-measure/).

## 4. Process inspection and acting on processes

- `/proc/<pid>/{stat,status,cmdline}` are readable for everyone (`/proc` has no `hidepid`).
  `fd/`, `fdinfo/`, `io`, `environ` need ptrace-read, so they work for own processes only
  (`/proc/1/io` is denied on the host). Yama `ptrace_scope=1` restricts attach only, not read.
- Open files: `readlink /proc/<pid>/fd/*`. Sockets: `socket:[ino]` joined to sock_diag dumps
  (TCP/UDP with addresses and `cgroup`; `UNIX_DIAG_PEER` and `UNIX_DIAG_NAME` for unix sockets,
  which also gives "connected to <process>"). `/proc/net/{tcp,tcp6,udp,udp6,unix}` carry the same
  data in text, also per netns. Use sock_diag: one dump, no parsing.
- **No standard polkit action for kill/renice.** GNOME System Monitor ships its own
  `org.gnome.gnome-system-monitor.policy` with kill and renice actions whose `exec.path` points
  at `gsm-kill` and `gsm-renice` (pkexec). KDE uses KAuth `org.kde.ksysguard.processlisthelper`.
  For processes inside a system unit there is a standard route: `org.freedesktop.systemd1.Manager.KillUnit`
  under `org.freedesktop.systemd1.manage-units` (host default auth_admin / auth_admin_keep active).
- **Renice**: raising niceness is free for own processes; lowering it needs `CAP_SYS_NICE` or
  `RLIMIT_NICE` (the host allows down to -11). With the `cpu` controller on in `user.slice`, nice
  only orders threads inside one cgroup. Across apps, `CPUWeight=` on the app's scope via the
  *user* manager's `SetUnitProperties` decides, and that needs no privilege.

**Recommendation**: own processes: signals and nice directly; "priority" for an app = scope
`CPUWeight`. Others: `KillUnit` where the pid is in a system unit; otherwise an `isle-process-helper`
run by pkexec under our own action (`org.isle.monitor.signal`, `.renice`, `auth_admin_keep`),
taking a pidfd-checked pid + start time so a recycled pid is never hit.

## 5. Sleep inhibitors

`org.freedesktop.login1.Manager.ListInhibitors` → `a(ssssuu)` (what, who, why, mode, uid, pid). The
host shows, for example, `["sleep","Isle","Locking the screen before sleep","delay",1000,1262234]`,
NetworkManager, UPower, RealtimeKit and Electron apps. Pids are the *taker*, so portal-routed
inhibits show Isle's own portal backend (the compositor), not the app. Isle must therefore
attribute its own portal and `zwp_idle_inhibit` / `org.freedesktop.ScreenSaver` inhibits to their
clients itself. Map pid → process → scope via `/proc/<pid>/cgroup`, with a pidfd to avoid reuse.
Activity Monitor's "Preventing Sleep" column = any `sleep`/`idle` block held by or for that app.
Evidence: [logind D-Bus API](https://www.freedesktop.org/software/systemd/man/latest/org.freedesktop.login1.html).

## 6. Keychain

- **oo7** 0.6.0 (crates.io 2026-02-21; 0.7.0-beta 2026-09-21), depends on zbus ^5.12 (the workspace
  is on zbus 5.19; zbus 6.1.0 is out, so watch 0.7). `oo7::dbus::{Service, Collection, Item}` is
  a plain Secret Service client (collections, items, label, attributes, secret, lock/unlock,
  create, delete, search), so it works against gnome-keyring 51 and oo7-daemon alike. `oo7::Keyring`
  picks the file+portal backend when sandboxed; Keychain is not sandboxed, so use `dbus` directly.
  Features: `tokio`, `native_crypto`. Arch ships `oo7` 0.6.0 in `extra` (not installed).
- **Classifying items** by `xdg:schema` (+ attributes):
  - Logins: `org.gnome.keyring.NetworkPassword` (user, server, protocol, port, domain, object),
    `org.epiphany.FormPassword`, `org.remmina.Password`, `org.gnome.OnlineAccounts`.
  - App secrets: `org.freedesktop.Secret.Generic` (go-keyring/Python keyring use
    `service`+`username`, and those *are* logins to show as "service — username"),
    `org.freedesktop.portal.Secret` (`app_id`, a sandboxed app's master key),
    `chrome_libsecret_os_crypt_password_v2` / `chromium_libsecret_os_crypt_password_v2`
    (`application`=chrome, chromium, claude…: browsers' and Electron apps' "Safe Storage" keys,
    so warn on delete), `org.freedesktop.NetworkManager.Connection` (agent-owned Wi-Fi secrets),
    and gcr's ssh passphrases with attribute `unique=ssh-store:<path>`.
  - Firefox keeps logins in `logins.json`+`key4.db` and does not use the Secret Service.
  - The host has **zero** website logins: Chromium-family logins live in the browsers, encrypted
    with the safe-storage key. "Passwords" on Linux shows app secrets and Wi-Fi unless Isle becomes
    a vault or imports from browsers. Scope decision.
- **Wi-Fi passwords**: `Settings.Connection.GetSecrets("802-11-wireless-security")`. NM source:
  `auth_start(…, get_modify_permission_basic(self), …)`, i.e. `settings.modify.own` when the
  connection lists exactly one user, otherwise `settings.modify.system`. Host profiles are
  `psk-flags=0` with empty permissions, so `modify.system` applies, and wheel+local makes that
  silent YES here. Keychain must gate the reveal itself (§7).
- **SSH**: gcr-ssh-agent is a proxy. It spawns `ssh-agent`, *preloads* `~/.ssh/*.pub` so
  `REQUEST_IDENTITIES` on `SSH_AUTH_SOCK` lists keys that are not actually loaded, runs `ssh-add`
  on first use, and saves passphrases under `unique=ssh-store:<path>`. "Loaded" truth is the
  inner socket `$XDG_RUNTIME_DIR/gcr/.ssh`. Query with `ssh-agent-lib` 0.6.0 (client side, tokio)
  over `ssh-key` 0.6.7.
- **Passphrases without argv or files**: best is to skip the CLIs. `ssh-key` (`encryption` feature)
  decrypts and re-encrypts OpenSSH keys (change passphrase), and `SSH_AGENTC_ADD_IDENTITY` via
  ssh-agent-lib loads a decrypted key. If calling `ssh-add`/`ssh-keygen`: set
  `SSH_ASKPASS=<isle askpass helper>` and `SSH_ASKPASS_REQUIRE=force` (`readpass.c` then always uses
  askpass, with no DISPLAY needed). Neither tool `closefrom()`s (only `sanitise_stdfd`), and
  `ssh_askpass` just `dup2`s stdout and execs, so an inherited pipe fd named in an env var reaches
  the helper. `ssh-keygen -p` asks up to three times, so the helper answers by prompt text.
- **Clipboard**: offer `x-kde-passwordManagerHint` = `secret` alongside the text (KeePassXC
  convention, honoured by Klipper). Isle's own clipboard history must skip such offers, and the
  app clears the selection after a timeout.
- **Passkeys**: see `docs/research/rust-desktop/passkeys.md` (2026-10-03). There is no Credential
  portal in xdg-desktop-portal 1.22.1 on the host (`/usr/share/dbus-1/interfaces` has only Secret);
  credentialsd 0.3.x needs a patched xdp. Not P19.
- **Certificates**: p11-kit `trust list` shows 170 anchors, 0 blocklist, 0 local anchors. A
  read-only "Certificates" list (plus `trust anchor --store`, which is root via pkexec) is cheap,
  but rarely used on this machine. Defer.

## 7. "Ask for your password before revealing"

- Polkit implicit values: `no`, `yes`, `auth_self`, `auth_admin`, **`auth_self_keep`**,
  `auth_admin_keep`. `_keep` retains a temporary authorization for the same subject for a brief
  period (about 5 minutes). It is listed by `EnumerateTemporaryAuthorizations` and revocable with
  `RevokeTemporaryAuthorizationById`, which gives a "Lock" button.
- An unprivileged app may `CheckAuthorization` with itself as subject and `AllowUserInteraction`.
  This is what GNOME Settings' unlock button (PolkitPermission) does. The prompt is drawn by
  Isle's own agent (`isle-polkit`), so it looks native, and fingerprint later comes free through
  polkit's PAM stack.
- The alternative is in-process PAM (`isle-auth` style, `pam_unix` → `unix_chkpwd`). It gives
  full control over the sheet but duplicates the agent and the retention logic.
- Caveat: same uid, so it is a UX gate, not a security boundary (any user process can read the
  unlocked keyring). macOS's gate is the same in practice.

**Recommendation**: ship `org.isle.keychain.reveal` (`allow_any=no`, `allow_inactive=no`,
`allow_active=auth_self_keep`), subject = the app's bus name, and revoke by id on the app's own idle
timer or Lock. Install the `.policy` with the package (`/usr/share/polkit-1/actions`). Evidence:
[polkit(8)](https://man.archlinux.org/man/polkit.8.en), [Authority D-Bus API](https://polkit.pages.freedesktop.org/polkit/eggdbus-interface-org.freedesktop.PolicyKit1.Authority.html).

## 8. Cleaner

- **Walker**: `jwalk` 0.9.0 is deprecated ("Use `dua-core` instead"). `dua-core` 5.0.1 (2026-10-25,
  Byron, from dua-cli, which dropped jwalk+rayon for its own crossbeam-deque walker and reports up
  to 40% faster) gives `walk`/`walk_roots`, never follows symlinks, and has a `Metadata` with
  `blocks/ino/dev/nlink`. It has no one-filesystem option, so filter on `st_dev`. `ignore` 0.4.34
  `WalkParallel` is gitignore-oriented (turn off `standard_filters`). Hand-rolled is
  `rustix` 1.1.6 `RawDir` (getdents64) + `statx(dirfd, name, AT_SYMLINK_NOFOLLOW, STATX_BLOCKS|INO|NLINK)`
  on a work-stealing pool. io_uring has `IORING_OP_STATX` but **no GETDENTS** (absent from
  linux-api-headers 7.1; the 2021/2023 series never merged), so it buys little.
- **Mounts**: the host mounts `/` (`@`) and `/home` (`@home`) from one btrfs device, both
  `noatime,compress=zstd:3`. With `noatime` a file's access time stays at its creation, so
  "not opened in" cannot be read from `atime`; the later of `atime` and `mtime` is a file's last
  use, and a view built on it says "changed", not "opened".
- **Sizes**: allocated = `st_blocks*512`; count a hard-linked inode once by `(dev, ino)` when
  `nlink > 1`. On btrfs with `compress=zstd`, `st_blocks` reports logical bytes: a 1.6 MB text log
  showed alloc/size 1.00. On-disk compressed size needs `compsize` (TREE_SEARCH, root), so show
  "size", not "disk".
- **Reflinks**: FIEMAP flags `FIEMAP_EXTENT_SHARED` on btrfs (Manana's 2022 series made the
  sharedness check far cheaper). Coreutils ≥9 `cp` reflinks by default, so copies in `~` are often
  shared, and deleting one frees ~0. Snapshots make everything shared: `@` has `/.snapshots`, so
  never trust "free" figures outside `@home`. Use `fiemap` 0.2.1 or the raw ioctl via rustix. Run
  FIEMAP only on candidates (large files, duplicate sets), not on every file.
- **Duplicates**: group by `(size)` ≥ a threshold, skip same `(dev,ino)` and already-shared
  extents, then xxh3-64 over the first+last 16 KiB (`xxhash-rust` 0.8.19, feature `xxh3`), then full
  `blake3` 1.8.7 (`mmap`+`rayon` for big files). Offer "replace with clone" (`FIDEDUPERANGE`,
  unprivileged on files you can write) on btrfs as well as delete-to-Trash.
- **System share** (each needs root):
  - Package cache 14G: `paccache -rk2` and `-ruk0` (pacman-contrib 1.13.1 installed).
  - Orphans: `pacman -Qdtq` (read, unprivileged) → `pacman -Rns`.
  - Journal: `journalctl --vacuum-size=` (47.5M here, not worth much).
  - Coredumps: `coredumpctl list` is readable for own dumps (ACL); deleting files in
    `/var/lib/systemd/coredump` needs root, and tmpfiles ages them out after 3d on CachyOS.
  - pkexec's default action `org.freedesktop.policykit.exec` is `auth_admin` with no keep and a
    generic "run /usr/bin/pacman" message. Ship one helper `/usr/lib/isle/isle-clean-helper` with
    fixed subcommands and its own actions (`exec.path` + `exec.argv1` annotations per pkexec(1),
    `auth_admin_keep`, readable messages). Never pass free paths or arbitrary argv.

**Recommendation**: `dua-core` for the walk, dedupe by `(dev,ino)`, FIEMAP only on candidates,
xxh3 prefilter then blake3. One helper and one policy file for the system share.

Evidence: [jwalk deprecation](https://docs.rs/crate/jwalk/0.9.0), [dua-core](https://docs.rs/dua-core/latest/dua_core/), [dua-cli v2.40](https://newreleases.io/project/github/Byron/dua-cli/release/v2.40.0), [btrfs fiemap sharedness](https://lab.nexedi.com/kirr/linux/-/commit/12a824dc67a61ec02ad2960f1856654febcd5d9d), [IORING_OP_GETDENTS series](https://lore.kernel.org/all/YGMIwcxAIJPAWGLu@wantstofly.org/T/), [compsize](https://github.com/kilobyte/compsize).

## 9. Rules file: KDL vs JSON

KDL (kdl 6.7.1, already the settings format) wins: comments, hand-editable rule lists
(`rule "Steam shader cache" path="~/.local/share/Steam/steamapps/shadercache" safe=#true`),
one parser in the tree, and round-trip formatting preserved for user edits. JSON only helps if
rules are fetched from a third-party feed, which nothing here plans. Use KDL with a version node.
