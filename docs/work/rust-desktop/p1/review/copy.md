# Review: copy

P1 stage 6. Every user-facing string in the structure sheets' Copy
sections, the strings the structure sheets quote elsewhere, and the 29
surface specs, checked against `structure/copy.md`'s rules and recurring
tables. Paths are relative to `docs/work/rust-desktop/p1/`.

## Summary

The copy is in good shape: no "OK" or "Yes", no exclamation marks, no
"please", no first-person system, no American spellings, "desktop" never
"workspace" or "Space" in anything the user reads, units spaced and
percent unspaced throughout. What is left is consistency. Placeholders
come in three syntaxes and two cases. Some "{Pane} Settings…" links do
not name their pane. A few errors stop after what happened and never say
what to do. A handful of strings are named two ways on two surfaces, and
some strings that recur across surfaces are missing from `copy.md`'s
tables. `copy.md` has no rule for typographic quotes and apostrophes, and
none for which names go in quotes. 0 blockers, 26 fixes, 30 polish.

## For the user

1. **Which names go in quotes.** The sheets quote some names and not
   others, even for one kind of name:
   - networks: "“{network}” needs a password", but "Couldn't connect to {network}."
   - widgets: "Install “{widget}”?", but "{widget} isn't installed." and "No room for {widget}."
   - folders: "“{folder}” was moved or deleted.", but capture's "{folder} is full."
   - files: "<file> couldn't be found."

   `copy.md` has no rule on it. **Recommendation:** add one. Curly quotes
   go round a name the user or the file system gave (file, folder, volume,
   network, VPN, widget, key, item title, process, query) inside a
   sentence. There are none round app, device or person names, or round a
   name standing alone as a label or title. That is macOS's practice and
   most of the sheets' already. Applying it changes these strings:
   - "Couldn't connect to “{network}”. Check the password and try again.": `structure/control-centre.md:463`, `structure/prompts.md:452`, and `copy.md:37`'s example, which becomes “Home Wi-Fi”
   - "“{widget}” isn't allowed to run.", "“{widget}” isn't installed.", "No room for “{widget}”…": `structure/widgets.md:483`, `:484`
   - "Couldn't save the screenshot. “{folder}” is full. It was copied instead.": `structure/capture.md:366`
   - "“{file}” couldn't be found. Showing the default wallpaper.": `structure/wallpaper.md:153`
2. **macOS's alert buttons in title case.** Rule 1 keeps Apple's case for
   standard menu items and system commands. The sheets also use it for
   macOS's alert buttons: "Keep Both", "Don't Allow", "Put Back", "Force
   Eject", "Try Again" and "Don't Save" (C3). Rule 1 does not say so.
   **Recommendation:** extend rule 1 to "…and macOS's standard alert
   buttons (Keep Both, Replace, Don't Save, Don't Allow, Try Again, Put
   Back, Force Eject, Empty Trash)". Isle's own buttons stay in sentence
   case. The other way, "Try again" and the rest in sentence case, would
   make Isle's alerts read unlike the Mac's.
3. **Accessibility and Energy Mode names (C36, C37).** These are the
   choice between sentence case and treating them as feature names.
   **Recommendation:** sentence case for the accessibility switches, as
   macOS's Settings writes them. Feature-name case for the Energy Mode
   values ("Low Power", "High Power"), which macOS treats as names.
4. **The wallpaper's menu (C11).** Rule 1's literal form is "Wallpaper
   Settings…", but macOS's desktop menu says "Change Wallpaper…".
   **Recommendation:** "Wallpaper Settings…", for one rule with no
   exceptions. If macOS's wording is kept, it is a standard item and
   takes Apple's case, "Change Wallpaper…", not "Change wallpaper…".
